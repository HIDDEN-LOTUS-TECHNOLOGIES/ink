Batch inscription cost

Pick one or more files. This page builds an ord envelope for each file in the browser and estimates a mainnet commit and reveal. Each file can be up to 390 KB, the same cap as the inscription cost page. A file over that limit is named and left out. The rest of the batch stays.

Estimate only. Nothing is signed or broadcast.

Formula

Each file is its own inscription. The commit is one P2TR key-path input and two P2TR outputs, 154 vbytes. The reveal is one P2TR script-path input and one P2TR output. The envelope matches the inscription cost page: a 32-byte placeholder, OP_CHECKSIG, then OP_FALSE OP_IF "ord", the content type, and the body in pushes of 520 bytes. The placeholder is only there so the script is the right length. No key is created.

witness bytes = 1 + 65 + compact size of the script + script + 34

reveal vbytes = ceil((378 + witness bytes) / 4)

Witness bytes count once toward weight. Bytes outside the witness count four times. Virtual size is ceil(weight / 4).

file sats = ceil(commit vbytes × sat/vB) + ceil(reveal vbytes × sat/vB) + postage

Postage defaults to 546 sats on every inscription. Changing it changes the sats locked in each reveal output. It does not change the virtual size. The totals row adds the file sats, so a fractional sat/vB is rounded up on each commit and each reveal before the files are summed. Recommended rates are the mainnet fastestFee, halfHourFee, hourFee, and economyFee from mempool.space. The custom sat/vB applies to every file. The optional USD line uses /api/v1/prices on the same host. Either request can fail and the size estimate still stands.

Reads /api/v1/fees/recommended and /api/v1/prices on mempool.space. No wallet, no keys, no signing, no broadcast.
